# 要件定義書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| プロジェクト名 | 五目並べゲーム (Gomoku) |
| 版数 | 1.0 |
| 作成日 | 2026-08-11 |
| 開発言語 | Python |
| 実行環境 | Windows GUIアプリケーション |
| 構成管理 | Git（ローカルリポジトリのみ、リモート無し） |

## 2. 目的

Claude Codeを用いたウォーターフォール型開発プロセス（要件定義 → コンポーネント設計 → 関数設計 → 実装 → テスト）の練習として、
Windows上でGUI操作により対局できる五目並べゲームを開発する。

## 3. 対象範囲

- 1台のPC上で、2人のプレイヤーが交互にマウス操作で石を置き合う対局機能
- CPU対戦・ネットワーク対戦は対象外（スコープ外）

## 4. 用語定義

| 用語 | 定義 |
|---|---|
| 盤面 | 石を置くための格子状のエリア。15行×15列の交点で構成される |
| 石 | プレイヤーが盤面の交点に置くマーク。黒石・白石の2種類 |
| 手番 | 石を1つ置く行為、およびそのプレイヤーの順番 |
| 五連 | 同色の石が縦・横・斜めのいずれかの方向に5つ連続して並んだ状態 |

## 5. 機能要件

### 5.1 盤面表示機能
- REQ-01: 15×15マスの盤面をウィンドウ内にGUIで描画すること
- REQ-02: 盤面の交点にマウスカーソルを合わせて視認できる程度の見やすさを確保すること

### 5.2 対局機能
- REQ-03: 2人のプレイヤー（黒石・白石）が交互に手番を持つこと。先手は黒石とする
- REQ-04: プレイヤーは盤面上の空いている交点をマウスクリックすることで、自分の色の石を置けること
- REQ-05: 既に石が置かれている交点をクリックした場合は、何も置かず手番を変更しないこと
- REQ-06: 石を置くごとに手番を相手プレイヤーに交代すること
- REQ-07: 現在の手番（どちらの色の番か）をGUI上に表示すること

### 5.3 勝敗判定機能
- REQ-08: 石が置かれるたびに、縦・横・斜め（右上がり・右下がり）のいずれかの方向に同色の石が5つ以上連続しているかを判定すること
- REQ-09: 五連が成立した時点で対局を終了し、勝者をGUI上に表示すること
- REQ-10: 盤面が全て埋まり、かつ五連が成立しない場合は「引き分け」としてGUI上に表示すること
- REQ-11: 対局終了後は、それ以上石を置けないようにすること

### 5.4 対局リセット機能
- REQ-12: 対局中・対局終了後を問わず、盤面をクリアして新しい対局を開始できる操作（ボタン等）を用意すること

## 6. 非機能要件

- NFR-01: 開発言語はPython（標準ライブラリのtkinterを使用し、追加パッケージのインストールを不要とする）
- NFR-02: Windows環境のGUIアプリケーションとして、ダブルクリックまたはコマンド実行で起動できること
- NFR-03: 1回のクリックから石の表示・手番交代までの応答は体感的に遅延なく行われること（目安1秒未満）
- NFR-04: ソースコードはGitでバージョン管理し、ローカルリポジトリのみで運用する（リモートリポジトリへの連携は行わない）

## 7. 制約事項

- CON-01: 対局モードは人対人のみとし、CPU対戦・通official対戦（ネットワーク対戦）は実装しない
- CON-02: 盤面サイズは15×15、勝利条件は5つ連続（五連）で固定とし、可変設定機能は設けない
- CON-03: 棋譜の保存・読み込み機能は本バージョンでは対象外とする
